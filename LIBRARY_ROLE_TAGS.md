# Ralph's library — role & phase tags (captured 2026-09-03)

Companion to `ROLES_AND_PHASES_PLAN.md`. Ralph tagged his ENTIRE live library
by multiple-choice in one sitting (~8 quick question rounds). This file is the
data: when the feature is built, this becomes the first migration. It is also
a live usability test of the classification itself — findings at the bottom.

Phases: exercises use the toggle (building / static); repertoire uses the
slider, captured here as four stops (unfamiliar → early learning → polishing →
performance-ready). ⚠️ Ralph's same-day caveat (practice session, video four):
four stops was too coarse — "performance-ready" here often means "played
before / could play it now, but I want it more solid" (e.g. Cuban Overture,
tagged performance-ready in the morning, technique-drilled that afternoon).
Read the right end of these tags as FAMILIARITY, not present readiness. His
original continuous-slider instinct stands ratified; the top of the scale
needs the most gradation.

## Design findings from doing this live (feed into ROLES_AND_PHASES_PLAN.md)

1. **Folders encoded roles FOR RALPH — hypothesis, not rule (his caveat,
   2026-09-03).** One folder-level question tagged 35 of 46 items in a single
   answer, but Ralph flagged the n=1 problem himself: "I don't know how other
   people will use folders... I don't want to assume anything." So for
   Undecided #2/#5: folder-based defaults may be offered as a CONFIRMED
   suggestion during batch tagging ("these look like one concert — all
   ensemble parts?"), never silently applied, and per-piece asking must
   remain the fallback for unorganized libraries.
2. **The trail really cannot infer phase — proven twice in one pass.** Frenzy
   has 33 passages of heavy practice and is *early learning*; Cuban Overture
   has almost no trail and is *performance-ready* (played in past seasons).
   Exactly the D57/D59 thesis, now with concrete examples.
3. **"Teaching material" is NOT a fifth role — Ralph's ruling (2026-09-03).**
   Lark 49 (a student's piece) first got tagged "teaching material," then
   Ralph rejected the distinction: "if I've put it in there, it's because I
   need to learn it in order to teach it" — the practice work is identical,
   so it's just Solo. Keep four roles. The test for ever adding a role: the
   app must behave differently because of it; revisit only if per-role coach
   behavior someday makes solo-piece coaching feel wrong on teaching pieces.
4. **The role question needs a "don't know / skip" path.** Ralph couldn't
   identify "Scerzo start" from its title. Forced-choice would have produced
   a junk tag.
5. **Roles are the player's call, not the material's.** Ralph tagged the Rose
   32 Etudes *solo/concerto*, not exercise — same book a student would tag
   differently. Don't auto-classify by repertoire lookup.
6. **Duplicates surface during tagging.** Two Mozart concerto documents came
   up; tagging made Ralph notice. A tagging pass doubles as library cleanup.
7. **A brand-new empty exercise can be "building".** All five I Love
   Articulation books are empty but tagged building — the toggle's initial
   value shouldn't assume static for new items.
8. **Ralph's own data is one-dimensional — known design blind spot (his
   flag, 2026-09-03).** His current life is ensemble parts + exercises, so
   the Solo and Audition roles are under-tested by his narrated sessions:
   "I'll miss some important design features because I'm not actually
   preparing solo repertoire or audition material right now." Mitigations:
   (a) a recital scheduled for February 2027 will start generating real
   solo-role practice data; (b) he plans to deliberately role-play audition
   prep using the DSO 2nd clarinet list to feel how that workflow differs
   from orchestral-part practice. Weight solo/audition design decisions
   accordingly until then — they rest on less evidence.
9. **The whole-library pass is cheap.** 46 items, ~8 multiple-choice rounds,
   minutes not hours. A one-time "tag your library" wizard at feature launch
   is viable, not a burden.
